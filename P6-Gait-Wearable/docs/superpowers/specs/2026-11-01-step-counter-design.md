# Step counter: design

**Date:** 2026-11-01 · **Assignment:** extend the P6 gait wearable so it counts steps with a neural net trained in
PyTorch, using every IMU sensor, with an uncertainty analysis, a Claude-made animation of how the system works
(net, PyTorch, back-propagation), a demo video and a short write-up. Builds on
`2026-10-23-gait-wearable-design.md`; everything there stays as it is.

## 1. Goal and shape

The thigh-worn UNO Q + MPU6050 keeps classifying STAND/WALK/RUN/BIKE and running the race; it additionally shows a
live **step count with an uncertainty** on a new **Steps** tab of the phone page. The count comes from a small
causal 1-D convolutional net ("StepNet") that reads all six raw IMU channels and outputs a step rate; the count is
the integral of that rate. StepNet is trained and evaluated in PyTorch on the Mac from recordings whose true step
counts the wearer counted out loud and typed in; the trained weights are exported to JSON and the board runs the
forward pass in pure Python (stdlib only, like the rest of the board code).

The MPU6050's seventh sensor, the die thermometer, is not used: it carries no step information and would only let
the net memorise sessions. The write-up says so.

Out of scope: per-step timestamps, gait-dependent gating of the counter (the net must learn by itself that biking and
fidgeting are zero steps), running PyTorch on the board, a new sketch (the current one already streams all six
channels at 100 Hz).

## 3. StepNet

**Input.** Six channels per sample (ax, ay, az in g; gx, gy, gz in deg/s) at 100 Hz, decimated by 4 to 25 Hz by
averaging each block of four consecutive samples (an incomplete trailing block waits for the next batch). Steps never
exceed about 3 per second, so 25 Hz keeps everything that matters and the board does a quarter of the work. Each
channel is then standardised: `(x - mean_c) / std_c` with per-channel statistics computed over the training
recordings and stored in the JSON.

**Body.** Causal dilated 1-D convolutions, all with kernel 5, left zero-padding of `(kernel-1)·dilation` so an output
at time t depends only on inputs at or before t:

| layer | in → out | dilation | activation |
|---|---|---|---|
| conv1 | 6 → 12 | 1 | ReLU |
| conv2 | 12 → 12 | 2 | ReLU |
| conv3 | 12 → 12 | 4 | ReLU |
| head | 12 → 1 (kernel 1) | 1 | Softplus |

Receptive field `1 + 4·(1+2+4) = 29` decimated samples = 1.16 s. About 1,800 weights. Output: non-negative **step
rate r(t) in steps per second**.

**Count.** `count(T) = Σ_t r(t)·dt`, `dt = 0.04 s`. The page shows `floor(count)`; the fractional value is in the
snapshot for the trace.

**Streaming on the board.** The counter keeps the last 28 normalised decimated samples (the receptive field minus one,
zeros before the first sample) as context. Every hop it runs the whole stack over `context + new samples` and keeps
only the outputs at the new positions. Because 28 equals the total left padding of the stack, those outputs are
bit-for-bit the same as an offline pass over the entire history (a test asserts this against the offline function on
random weights). A FIFO reset (the sketch's reset counter changed) clears the context and the decimation remainder but
keeps the count. Cost: roughly 75k multiply-adds per 0.5 s hop in pure Python, well under the hop on the UNO Q.
If `numpy` imports on the board, `stepnet.py` uses it for the convolutions; both paths produce identical results
(tested) and the pure-Python path is the one that must exist.

**Weights file** (`models/stepnet.json`):

```json
{"rate_hz": 25, "decimate": 4, "dt": 0.04, "kernel": 5,
 "mean": [6 floats], "std": [6 floats],
 "layers": [{"w": [[[k floats] × in] × out], "b": [out floats], "dilation": 1, "act": "relu"}, ..., {"...": "softplus"}],
 "meta": {"trained": "2026-11-02T18:00:00", "recordings": 26, "epochs": 400,
          "loro": {"mae_steps": 1.9, "mape_pct": 4.1, "bias_steps": -0.3, "pm_pct95": 9.5},
          "seed_std_steps": 0.8}}
```

`meta.loro.pm_pct95` is the 95th percentile of the absolute percentage error over the leave-one-recording-out
predictions of non-zero recordings; the page shows `count ± ceil(count · pm_pct95 / 100)` (at least ±1 once the
count is non-zero). Before training exists, `models/stepnet.json` is a seed file with small random weights and
`pm_pct95 = 100` so the app runs end-to-end; tests use `tests/seed_models.py` to build their own, as today.

## 4. Recording counted takes

A **counted take** is a single-activity recording of open-ended length whose true step count the wearer types when
stopping. Activities: `WALK`, `RUN`, `STAND`, `BIKE`, `MIXED` (`STEP_ACTIVITIES` in `recorder.py`; `MIXED` is any
sequence the wearer likes, e.g. stand, walk, stop, walk). The label column holds the activity for every row (no
get-ready gap: the wearer starts walking after tapping Start, and standing at the beginning is real data).

- `Recorder.start_counted(activity, who="")` opens `<stamp>-steps-<activity>-<who>.csv` (activity lower-case, who
  omitted when empty) with a 1-hour cap instead of a script end.
- `Recorder.stop(steps=None)`: when the active take is a counted one and `steps` is an int ≥ 0, the file is closed and
  renamed (never over an existing file: `-2`, `-3`, ... until a free name) to `<stamp>-steps-<activity>-n<steps>[-<who>][-2].csv`; without `steps` it keeps its name (the training loader
  ignores files without a count). `stop()` on a guided or single take ignores `steps`; a negative `steps` raises `ValueError`. `stop()` returns the final file name (`None` if no take was open) so the caller can tell the wearer when a count could not be saved. The `n` marks the count so a take stopped without one, whose `who` is numeric or starts with a digit, can never parse as counted.
- `recorder.status()` gains `"kind": "guided" | "single" | "counted" | None` and `"elapsed_s"` (seconds since the take
  started) so the page can show a running clock.
- File-name grammar, parsed by `recorder.parse_counted(name) -> (activity, steps, who) | None`, shared with the
  trainer: `^\d{8}-\d{6}-steps-(walk|run|stand|bike|mixed)-n(\d+)(?:-([A-Za-z0-9_-]+?))?(?:-2)?\.csv$`.

Protocol for the wearer (goes in the README and on the tab): about 25 takes of 15 to 40 s, counted out loud:
walk slow ×3, walk normal ×4, walk fast ×3, run ×4, stand with fidgets ×3 (0), air-bike ×3 (0), mixed ×5.
After training, three more fresh counted walks are recorded for the demo video and never trained on.

## 5. Pipeline and web

`Gait.__init__(model1, model2, recorder, rate, clock, races_path=None, stepnet=None)`; `main.py` passes
`StepNet.load(MODELS / "stepnet.json")`. `Gait.steps` is a `StepCounter(stepnet)`.

- `on_batch`: after pushing to the ring, `self.steps.on_samples(samples)` (under the gait lock; the counter only appends
  to a pending list there). On a reset-counter change, `self.steps.reset_context()`.
- `tick`: on every hop (the existing `HOP_S` cadence), `self.steps.process()` runs the net over the pending samples,
  before classification, so the count advances even while the window is not yet full.
- `snapshot()` adds `"steps": {"count": int, "exact": float, "rate": float (steps/s, last decimated sample),
  "spm": int (rate·60), "pm": int (half-width in steps), "wave": [rate values of the last 4 s at 25 Hz]}`.
- `StepCounter.reset()` zeroes the count and the trace, keeps the context.

Routes added to `web.py`: `GET /steps` serves the page (opens on the Steps tab, like `/race`);
`POST /record?label=WALK&steps=1&who=` starts a counted take (`label` must be in `STEP_ACTIVITIES` when `steps=1`;
without `steps=1` the route behaves as today); `POST /stop?steps=N` stops a counted take with its count (`steps`
must be a non-negative integer, else 400); `POST /steps/reset`. The `/data/<csv>` download and `sessions` listing cover
the counted files unchanged.

Page, Steps tab (third tab in the bar; `showTab("steps")`):
- a large count, e.g. **38 ± 2**, the activity verdict small beneath it, cards for steps/min and the running time of
  the current take;
- a canvas with the last 4 s of the step rate (spikes once per step); the gait wave canvas stays on the Gait tab;
- a **Reset** button (`/steps/reset`);
- a recording card: five activity buttons, the shared `who` field, **Start**, then while recording the elapsed clock
  and row count and a **Stop** button; on Stop the card asks "How many steps did you count?" with a numeric input,
  **Save** (`/stop?steps=N`) and **Discard** (`/stop`). The input is pre-filled with the device's own count for that
  take (the page remembers the count when Start was tapped and subtracts it) so the wearer sees the comparison but
  must still confirm or correct it.

## 6. Training (`train/steps.py`, `train/stepnet_torch.py`)

**Dataset.** Every `data/*-steps-*-n<N>[-who].csv` with a parsable count. Rows are loaded like `train.py` does today
(truncated last row skipped); a take with a break in `t` over 0.8 s (`train.py`'s threshold: FIFO overflow or
re-probe, samples lost, so the typed count no longer matches) is skipped with a printed warning. Rows are decimated with `stepnet.decimate`, normalised with mean/std computed over the training
fold only. Each item: `x` of shape `(6, T)`, target `N`, activity, who.

**Zero segments.** Each run of STAND or BIKE rows lasting 5 s or more in the older guided session files
(`data/*-guided-*.csv`, a label per row; a run ends at a label change or a break in `t` over 0.3 s, length = rows / 100 Hz)
is added as an exact zero-step recording (`load_zero_segments`, name `file:LABEL@<start>s`, who `guided`). They are in
every training fold (LORO and the seed spread) but never held out, so every metric is over counted takes only; WALK/RUN
runs have no count and are not used. They teach that leg motion without footfalls is not a step. Measured on 6
counted takes, together with the wider gain: held-out walk MAE 4.06 → 2.33 steps (mean of 3 seeds).

**Model.** `StepNetTorch(channels=12, kernel=5, dilations=(1, 2, 4))` with the same layers as §3, left padding via
`F.pad`, `Softplus` head; `forward(x: (B, 6, T)) -> rate (B, 1, T)`; `count = rate.sum(-1) * dt`.
`export(path, mean, std, meta)` writes the JSON of §3. A test loads the export into `stepnet.StepNet` and checks the
pure-Python output equals the torch output within 1e-5 on random input.

**Loss.** `SmoothL1(count_pred, N)` per recording (beta 1.0), in steps. Zero-count recordings pull the rate to zero
during pedalling and fidgeting. (A relative loss, divided by `max(N, 5)`, was tried and dropped: on the synthetic
probe it made the cadence response less reliable across seeds, not more.)

**Augmentation** (all count-preserving; pairing, rotation and gain each with probability 0.5 per item per epoch, in
that order, then the time-stretch on every item):
- *pairing*: concatenate with another random recording, targets add;
- *frame rotation*: one random rotation of up to 15° about a random axis applied to both the accel and the gyro
  vectors (the strap sits differently each day);
- *gain*: multiply all channels by `U(0.5, 1.5)` (wide, so signal amplitude stops being a usable shortcut for the
  count);
- *time-stretch*, always: linear resampling by a factor `U(0.7, 1.3)` at 25 Hz. The same count over a new duration
  is the signal that makes the rate follow the cadence; without it (or at probability 0.5 with `U(0.85, 1.15)`) the
  net learns "time spent moving × ~1.85 steps/s" and a 44-step walk at 1.6 / 2.3 Hz reads 52 / 36.
Augmentation happens after decimation, before normalisation, on the training fold only.

**Fit.** One recording per optimiser step (variable lengths, no padding), Adam, lr 3e-3 for 300 epochs then 3e-4
for 100 (`EPOCHS = 400`, the drop at 75 %), seed fixed. A fit takes seconds on the Mac. The cadence response appears
late: on the synthetic probe a 300-epoch fit is within 10 % at all four cadences for 6 of 8 seeds, a 400-epoch fit
for 8 of 8. Dilations `(1, 2, 4, 8)` were tried and gave no reliable gain, so the board net stays `(1, 2, 4)`.

**Evaluation and uncertainty** (`--report`):
- *Leave-one-recording-out*: for each counted take, fit on the others plus all zero segments and predict its count. Per recording: predicted,
  true, error (steps), percentage error (non-zero recordings). Summary: MAE in steps, MAPE, signed bias, bootstrap
  (2000 resamples) 95 % interval of the mean percentage error, `pm_pct95` (`null` when no recording has steps; the
  board then shows ±100 %), and the same MAE/bias per activity.
- *Seed spread*: 5 fits on all counted takes and zero segments with different seeds; per-take standard deviation of
  the predicted count, summarised as `seed_std_steps` (mean over the counted takes). This is the net's own variability.
- *Hold-out demo takes*: recordings whose `who` is `demo` or ends in `-demo` are excluded from training and LORO and reported
  separately as "fresh takes the net never saw" (this is what the video shows).

**Outputs.** `models/stepnet.json` (final fit on all non-demo counted takes plus the zero segments; `meta.recordings` = counted takes, `meta.zero_segments`), `docs/steps_results.md` (tables of the
above), figures via `train/steps_plots.py`: `steps_scatter.png` (true vs predicted, LORO, coloured by activity, with
the ±pm band), `steps_errors.png` (histogram of LORO errors), `steps_rate.png` (one walk: the six traces, the rate
curve, the cumulative count against the typed count), `steps_training.png` (loss curve). The write-up embeds these.

**CLI.** `train/steps.py [--report] [--epochs N] [--seed S] [--data DIR]`; default = fit + export, keeping the
previous export's `meta.loro` (and its `trained` stamp as `meta.loro_from`) so the live ± survives a plain refit.
`--report` adds LORO, the seed spread and the demo takes, writes `docs/steps_results.md` first and then the figures
(a figure error cannot lose the results). `train/requirements.txt` gains `torch`.

## 7. Animation (`docs/animation/`)

Manim Community (installed in `.venv`, `docs/animation/requirements.txt`: `manim`), `Text` only (no LaTeX), 1080p
30 fps, 60 to 90 s, captions on screen, no audio. Scenes, each a Manim `Scene` composed by `render.sh` into one MP4:

1. **The wearable**: a thigh with the board; six traces scroll out of the sensor, labelled ax…gz.
2. **Decimate and normalise**: four samples merge into one; the traces centre and scale.
3. **The net**: three stacked conv layers drawn as rows of units with dilated connections fanning left into the past;
   a window of input slides and a single output value appears per time step.
4. **Rate to count**: the output curve spikes at each step; the area under it fills and a counter ticks up.
5. **Loss**: the final count is placed beside the typed count; the gap becomes the loss number.
6. **Back-propagation**: arrows run backwards through the layers, each weight gets a small coloured nudge
   (gradient sign), the loss shrinks, the loop repeats a few times fast.
7. **Ship it**: the weights become a JSON file that flies to the board; the phone shows the live count.

Rendered file: `docs/animation/stepnet_explainer.mp4` (git-ignored if over 10 MB) plus a sub-5 MB
`stepnet_explainer_small.mp4` for Notion made with the existing AVFoundation shrink tool.

## 9. Error handling and tests

- Malformed or missing `stepnet.json` → `main.py` logs and runs with `stepnet=None`; the snapshot's `steps` is then
  `None` and the tab shows "no step model".
- `/stop?steps=` not an integer or negative → 400; `steps=1` with an activity outside `STEP_ACTIVITIES` → 400.
- Renaming a take whose target name exists (two takes in one second) appends `-2`, as today.
- Training with fewer than 3 counted recordings exits with a clear message; `--report` needs at least 4.

Tests (pytest, in `tests/`): `test_stepnet.py` (decimation remainder handling; pure-Python conv on a hand-computed
3-sample case; streaming == offline on random weights over random chunk sizes; numpy path == pure path when numpy is
present; reset keeps the count and clears the context; JSON load validation), `test_steps_train.py` (skipped
without torch: torch forward == `stepnet` forward after export; a 400-epoch fit on synthetic step recordings from
`tests/synth.py` gets every count within 6 steps and counts 44-step walks it never saw at 1.6-2.3 Hz within 10 %
with the rate tracking the cadence; the torch net is causal; augmentations preserve length rules and targets add on
pairing; LORO runs on 4 synthetic recordings; the loader skips gapped takes and sorts out demo takes), extended `test_recorder.py` (counted take file name, rename on stop with a count,
no rename without, `parse_counted`), `test_web.py` (`/steps`, `/record?steps=1`, `/stop?steps=`, `/steps/reset`,
400s), `test_pipeline.py` (`steps` in the snapshot advances on synthetic walking, reset, `stepnet=None`).
Existing 57 tests keep passing.
